# PS5ish Modular Shell 产品需求文档

**版本：v0.1 | 日期：2026-09-05 | 状态：开发前需求基线草案**

**产品定位：以 PS5ish 为首个视觉主题、运行于 Windows 客厅大屏的模块化娱乐界面。采用最小宿主、可组合主题和独立能力插件，逐步接入游戏、奖杯、影视与游戏内快捷面板。**

本文件区分三类内容：用户已明确的目标、为执行目标建议采用的设计，以及必须经过原型验证的技术假设。文中的接口、包名和版本号示例属于本项目拟定义的契约，不是现有 Playnite 或第三方插件已经提供的 API。尚未在目标 PC 上编译、安装或实测。

## 1. 目标、范围与优先级

### 1.1 已明确的使用环境和产品方向

运行环境为 85 寸及以上电视与 Windows PC。游戏以 Steam 为第一阶段数据来源，后续兼容 Playnite 已接入的其他平台和本地游戏。影视后端使用 Emby。沙发距离的手柄操作是主要使用方式，键鼠用于开发、配置和补充操作。

视觉优先于功能数量。首个正式主题保留 PS5ish 的布局语言与主机感，不替换为其他主题。选中游戏或影视内容时，先显示剧照或背景，再淡入音乐，稳定停留后播放视频。游戏与影视共用浏览规则，但不强行共用业务数据库。

系统必须允许边使用边迭代。主题本身、数据接入、成就、通知、影视和未来快捷面板都应具有清晰边界；新增能力应优先通过外挂插件完成，而不是不断扩充宿主。

### 1.2 产品优先级

| 优先级 | 范围 | 定义 |
| --- | --- | --- |
| P0 | 最小宿主、主题组合机制、Steam 游戏浏览、沉浸预览、启动返回 | 第一版交付必须完成；模块化和视觉质量均属于 P0 |
| P1 | 素材维护增强、Steam 奖杯页与解锁通知 | 核心游戏体验稳定后实施，成就始终为可选插件 |
| P2 | Emby 首页分区、影视海报墙、正片播放与观看状态 | 同一套大屏浏览体验，不以跳转另一个应用首页代替整合 |
| P3 | 游戏内快捷呼出面板 | 前述目标完成后的独立扩展项目 |

P0 不要求完成插件市场、可视化主题编辑器、任意主题全量热切换、跨平台客户端、自动更新系统、全平台成就和自研完整视频播放器。远期功能不应成为首版上线的前置条件。

### 1.3 成功标准

“最小”减少页面、内容数量和集成范围，不降低关键路径的完成度。第一版可以只有约十款精心维护的游戏，但必须漂亮、流畅、可用，且能够在不改变架构的前提下继续增加内容。

模块化必须通过行为验证：不安装成就、Emby 或快捷面板，主页仍正常；替换预览播放器不改主题布局；新增配色与动效包不改业务插件；符合现有契约的新插件能够独立构建、安装和禁用，不需要重新编译宿主。

## 2. 总体方案与架构边界

### 2.1 推荐路线

以 Playnite 承担现有游戏库、平台接入与游戏启动能力；开发一个轻量伴生宿主，承接通用展示和扩展契约；将 PS5ish 改造为首个可组合主题。暂不 fork Playnite 本体，也不为使用 CSS 而重写成 Electron 或独立 Web 启动器。

Playnite 的主题基于 WPF/XAML，而非浏览器 CSS；本项目将“CSS 模块化”的诉求落实为设计变量、资源字典、控件模板、布局、动画和主题资产的分层。[S01] Playnite 已支持插件向主题暴露自定义控件，但具体控件需要双方适配，不能假定所有插件天然可接入。[S02][S03]

### 2.2 最小宿主只保留通用能力

| 层级 | 职责 | 不得承担的职责 |
| --- | --- | --- |
| Playnite 平台层 | 游戏库、现有平台插件、启动与会话信息 | 不创建电影伪游戏条目，不重写 Steam 登录体系 |
| Shell.Host 宿主 | 契约注册、生命周期、导航与焦点、主题组合、预览协调、基础诊断 | 不包含 Steam 成就规则、Emby 查询、素材站点抓取逻辑 |
| Theme Packages 主题包 | 设计变量、组件模板、布局、动效、图标和声音资源引用 | 不直接联网，不查询插件私有数据库，不自行启动播放器 |
| Capability Plugins 能力插件 | 内容来源、素材来源、音乐与视频后端、成就、通知、影视功能 | 不任意修改其他插件文件，不绕开宿主争抢焦点和声音 |
| Companion Apps 外部应用 | SAN、未来快捷面板或成熟播放后端 | 不被假定为可直接嵌入的 Playnite 库 |

宿主保留通用预览状态机和媒体协调规则，但音视频解码、第三方音乐管理和数据抓取位于插件。静态图片浏览可作为安全回退。宿主不需要知道“这是一枚奖杯”，只需要知道某个插件向指定区域提交了可展示内容。

### 2.3 两种交付组合

**最小可用组合：**宿主 + 默认安全主题/PS5ish 基础主题 + Playnite 游戏接入模块。支持封面、背景、导航、启动和返回，不依赖成就、Emby、音乐或视频插件。

**首版推荐组合：**最小可用组合 + 音乐后端 + 视频后端 + 至少一种可用素材来源。完成用户要求的沉浸预览。默认随产品交付不等于强制依赖；移除音视频插件后，应退回静态浏览，而非无法启动。

这是产品组合与技术依赖的区别。不能为了声称“极小核心”而交付缺少核心体验的首版，也不能为了首版好用而把所有功能写死在宿主里。

### 2.4 插件承载与工程规模

建议 Playnite 只负责加载本项目的 Shell.Host 伴生扩展；本项目能力插件采用独立构建产物、清单和统一注册契约，由 Shell.Host 在启动时发现和注册。现有 Playnite 插件仍由 Playnite 自己加载，本项目通过适配模块接入，不将任意 `.pext` 或 DLL 当作本项目插件直接装载。

P0 只实现本地目录发现、清单检查、能力注册、启停配置和启动时装载，不实现插件市场、复杂依赖求解器或任意程序集热卸载。禁用或升级代码插件可以要求重启。跨插件契约共享、初始化顺序和程序集依赖必须在 M0 原型中验证；若受宿主限制，则改为独立 Playnite 扩展承载，保持业务契约不变。

首版采用单仓库、少量项目和本地调用。模块化不要求微服务化，不引入消息队列、Kubernetes 或没有实际调用方的 HTTP 服务。

## 3. 主题系统需求

### 3.1 主题必须可组合，而不是复制整套工程

| 编号 | 必须支持的模块 | 要求 |
| --- | --- | --- |
| TH-01 | 设计变量 | 颜色、字体引用、字号、间距、圆角、阴影、焦点强调和安全边距可集中调整 |
| TH-02 | 基础组件 | 游戏卡、影视卡、横向内容条、海报网格、详情摘要、按钮、提示和弹层具有稳定模板契约 |
| TH-03 | 页面布局 | 首页、游戏库、详情页、设置页可分离维护；影视插件可增加自己的页面布局 |
| TH-04 | 动效包 | 焦点移动、背景淡入、卡片过渡、页面切换可替换，不能改变业务状态机 |
| TH-05 | 氛围资产包 | 背景、图标、界面音效和全局音乐引用可独立替换，不覆盖每款内容的手动素材选择 |
| TH-06 | 插件外观适配 | 成就或影视插件的外观通过可选适配字典/模板提供，不进入主题必需依赖 |
| TH-07 | 主题预设 | 保存所选布局、配色、动效和资产包组合；切换主题不改变内容库、进度或账号 |
| TH-08 | 兼容与回退 | 缺少资源、槽位或版本不兼容时，在应用前阻止或回退至默认主题，并保留诊断信息 |

首个布局包为 `layout.ps5ish`。P0 至少提供两套明显不同的配色/氛围预设，验证共用布局与插件代码。P1 再通过不同密度或不同内容条布局验证结构级扩展；不要求首版制作第二套完整主机界面。

### 3.2 组合和覆盖规则

建议每个预设选择一个主布局、一个主配色、一个图标包和一个动效包。扩展包只能覆盖清单中声明的资源，不允许无限制覆盖全局控件样式。存在结构约束的组件必须声明适用布局和契约版本，不承诺任意包之间都可组合。

资源优先级应固定并可诊断：基础默认值 → 主题默认值 → 所选扩展包 → 用户主题覆盖。内容级图片、音乐和视频覆盖单独管理，不与界面皮肤覆盖混用。继承仅允许单父级或明确有序组合，拒绝循环依赖与不明确的多重覆盖。

在 WPF 实现中，可采用合并资源字典和有限使用的动态资源。WPF 自身存在资源作用域和覆盖顺序，因此必须由组合器统一生成加载次序，不能仅靠文件命名约定保证效果。[S04]

### 3.3 主题与插件之间的稳定边界

主题引用宿主定义的设计变量、展示模型和命令，不直接绑定某个第三方插件的私有字段或绝对文件路径。第三方控件必须经专门外观适配层接入。能力插件应提供可用的默认展示模板，主题可以覆盖，未覆盖时使用默认模板。

**TH-09：缺少插件时，不加载引用该插件 CLR 类型或程序集资源的 XAML 字典。仅将控件设为隐藏不足以作为缺依赖保护。**模板能否加载和加载后是否可见是不同问题，必须分别测试。

**TH-10：主题不得通过自有定时器决定音乐或视频何时开始。**动效可以表现状态转换，但启动、取消、静音和恢复均由宿主协调器决定。

### 3.4 大屏与控制器要求

**TH-11：**优先适配目标电视实际使用的 16:9 大屏输出，首版以 4K 界面为验收目标，并验证 Windows 常用缩放下不裁切。实际刷新率、显卡、缩放和观看距离在 M0 登记，不预先假定电视或 PC 能力。

**TH-12：**中文标题、长标题、缺失 Logo 和混合封面比例有明确排版策略；影视竖海报不得被强行拉伸为游戏方卡。每个聚焦、禁用、加载和错误状态都要有视觉定义。

**TH-13：**所有消费场景可用手柄完成；插件移除、页面返回和空列表必须有可预测的焦点去向。提供减少动态效果、关闭自动视频、夜间低音量设置。

**TH-14：**P0 允许主题切换后重新载入界面或重启 Playnite。配色的即时预览可后续增加，不将完整热换肤列为首版强制条件。

## 4. 能力插件系统需求

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| PL-01 | 独立交付 | 插件可单独构建、安装、升级和删除；不是编译进宿主后仅提供开关 |
| PL-02 | 清单契约 | 声明插件标识、版本、宿主契约范围、能力、依赖、设置入口和加载方式 |
| PL-03 | 能力发现 | 消费方查询能力和可用状态，不在核心内按插件名称分支 |
| PL-04 | 生命周期 | 初始化、启用、停用、资源释放和异常状态有统一入口；启动顺序可预测 |
| PL-05 | 故障回退 | 可捕获的超时或插件异常只影响对应能力，空槽位自动收起，不阻止基础浏览 |
| PL-06 | 配置与数据 | 每个插件有自己的配置、缓存和状态版本；删除插件默认不删除用户数据 |
| PL-07 | 可诊断性 | 显示启用状态、失败原因、依赖版本和可用能力；记录最近失败与恢复 |
| PL-08 | 独立样例 | 交付一个可安装、可移除的演示插件，向首页插槽添加简单内容，证明接口有效 |

### 4.1 插件分类

内容源插件负责提供游戏、电影、剧集等条目；素材插件负责图片、音乐和视频候选；播放后端负责播放命令；功能插件负责成就、笔记等领域功能；通知插件负责提示的渲染；外部应用适配插件负责能力探测和启动/状态衔接。

一个插件包可以提供多个相关能力，但不得把互不相关的领域强制绑定。例如奖杯页与成就数据适配可以同包，Emby 不应成为它的依赖。

Playnite Achievements、Extra Metadata Loader、Extra Metadata Fullscreen Mode Helper、UniPlaySong 和 SAN 是候选集成对象，不是产品需求本身。EML 已有主题控件接口，UniPlaySong 已有音乐预览与主题控制能力，但具体控制粒度仍需验证。[S05][S06]

### 4.2 依赖和冲突规则

强依赖缺失时只禁用依赖它的插件；软依赖缺失时减少对应能力。内容列表、详情字段和通知后端分别解析依赖，不以“安装了插件”直接推断全部能力都可用。

同一个上下文的音乐播放、预览视频和通知输出分别只能有一个生效后端。可以配置候选和回退次序，但不能让两个后端同时竞争。异步查询、重试和事件订阅均应有取消与释放机制。

同进程插件并不具有完整的安全或崩溃隔离。P0 提供逻辑级异常处理和安全启动，不能承诺拦截任意原生崩溃或恶意代码。需要强隔离的外部播放器、下载进程或快捷面板，后续使用独立进程。

### 4.3 信任边界

P0 只支持用户明确安装的可信本地插件和开发者主题。配置化配色/资产包与包含 XAML/代码的开发者包必须分级显示。不得将任意 XAML、脚本或 DLL 描述成无风险皮肤。

权限清单首先用于透明展示和宿主接口授权，不声称它能限制同进程代码直接访问操作系统。校验包路径、防止越界覆盖、拒绝不支持的契约版本；不默认开放公网控制接口。

## 5. 扩展契约与界面插槽

### 5.1 首版契约范围

以下为拟定义的职责，不强制采用这些接口名称。

| 契约 | 提供内容 | 约束 |
| --- | --- | --- |
| ContentProvider | 分页条目、条目详情、主操作能力 | 返回统一内容引用，不暴露后端数据库对象 |
| AssetProvider | 图片、音乐、视频候选及来源信息 | 只提供候选，不自行播放 |
| PreviewBackend | 准备、播放、停止、静音、就绪/失败事件 | 接受上下文与取消信号；报告实际支持能力 |
| ContributionProvider | 页面、分区、字段、动作和设置项 | 声明插槽、顺序、上下文条件和焦点行为 |
| CommandHandler | 启动、打开详情、播放预告等命令 | 显式声明支持的内容类型和失败结果 |

成就的详细数据契约属于成就模块的扩展契约，不要求最小核心预置奖杯、DLC、白金或排行榜字段。影视播放契约和快捷面板契约在相应阶段增加，不提前冻结无调用方的接口。

### 5.2 初始插槽

| 插槽 | 用途 | 未提供内容时 |
| --- | --- | --- |
| home.primary | 首页主内容条，初始为游戏 | 显示可恢复的空库引导 |
| home.sections | 最近内容、精选或后续影视分区 | 收起空分区，不留下大片空白 |
| details.summary | 详情摘要、奖杯概览等 | 保留基础详情 |
| details.actions | 播放、追踪、笔记等操作 | 仅保留当前可执行操作 |
| settings.sections | 插件设置入口 | 未安装插件不显示入口 |

通知输出通道在 P1 增加；游戏内快捷面板插槽在 P3 实现，不为了预留而在 P0 建空进程。插槽需要有版本、布局约束和键盘/手柄导航约定，不是允许插件任意覆盖整个屏幕。

### 5.3 事件、命令与线程规则

事件用于报告已发生的事实，例如选中内容变化、游戏会话变化；命令表达用户意图，例如启动条目。事件携带内容引用、上下文编号和发生时间。高频选中事件需要合并或取消旧工作，不能无限排队。

远程请求不阻塞 UI；适配层负责把需要的操作转回 UI 线程。订阅随插件停用解除。P0 不实现通用分布式事件总线；宿主内回调和受控事件分发已足够。

## 6. 游戏与沉浸预览需求

### 6.1 游戏基础体验

**GA-01：**读取 Playnite 已维护的游戏、封面、背景、安装状态和最近游玩信息。Steam 为首个验收平台，不另建一份与 Playnite 竞争的游戏主数据库。

**GA-02：**首版至少提供首页、全部游戏、游戏详情与基础设置。支持继续从先前位置浏览、启动游戏、启动失败提示和退出后回到原条目。

**GA-03：**后续接入其他平台和本地游戏，不改变通用内容模型。没有平台成就接口的本地游戏仍可作为普通游戏浏览和启动，不伪造可读取成就能力。

### 6.2 预览时序

以下数值为建议初值，属于产品调校参数，不代表 PS5 实际系统参数。

| 状态 | 触发条件 | 画面与声音 |
| --- | --- | --- |
| 新选择 | 焦点移到内容 | 立即更新焦点和文字；显示缓存背景；取消旧预览 |
| 静态预览 | 稳定停留约 200 ms | 开始当前音乐，约 700 ms 淡入 |
| 视频准备 | 停留约 2.5 秒且允许自动播放 | 后端准备视频；背景图继续保留 |
| 视频预览 | 当前内容的视频就绪 | 约 300–500 ms 淡入视频，不出现黑场 |
| 离开/暂停 | 焦点切换、进入游戏、进入正片或失去前台 | 旧请求失效；停止或淡出相关音视频 |
| 恢复 | 返回主页且重新获得焦点 | 恢复原内容，按当前状态重新计算预览，不恢复过期任务 |

### 6.3 两种声音模式

**PR-01：**默认建议采用“氛围预览”：主题音乐继续，视频静音；用户可以将全局或单个内容改为“预告原声”：视频就绪后淡出音乐，由视频声音接管。此默认值属于建议，应在首版体验验收时确认，不删去任一模式。

**PR-02：**提供主动播放完整预告的操作，与自动背景预览分开。主动播放可显示播放控制，退出后回到原内容。禁用自动视频不影响用户主动观看预告。

### 6.4 状态一致性和回退

**PR-03：**每次内容选择创建新的 generation/context 标识。异步图片、音乐、视频和计时器返回时必须检查上下文，任何过期结果不得改变当前界面或声音。

**PR-04：**视频在首帧可显示前不得移除背景。没有可靠首帧信号的后端必须通过原型验证其替代策略；无法避免黑场的后端不纳入默认组合。

**PR-05：**至多一个当前预览视频处于活动解码状态；相邻内容可做有限素材预取，不能为整面海报墙同时启动播放器。受控音频淡入淡出期间允许短暂重叠，其他情况不得多路播放。

**PR-06：**无视频时保留图片与音乐；无音乐时保留图片或静音视频；所有素材缺失时使用可识别的安全卡片。失败不重复刷提示，不阻止启动游戏。

**PR-07：**游戏启动前释放主页媒体；启动失败恢复浏览；游戏运行中主页不得自行恢复声音。插件通知声音与主页音乐分属策略，不因此擅自调整游戏音量。

**PR-08：**预览策略作用于统一内容引用。接入影视后复用同一套取消、声音协调和首帧规则，不复制第二套状态机。

## 7. 内容与素材维护

### 7.1 最小展示模型

通用展示模型只包含稳定引用、内容类型、标题、图片集合、预览描述、主操作和能力集合。类型支持游戏、电影、剧集、单集，但最小宿主不处理其具体领域逻辑。

内容引用建议由 provider、sourceInstance 和 itemId 组成。Steam App ID、Playnite ID 和 Emby Item ID 通过适配层关联，不能互相混用。Emby 服务器标识属于内容命名空间，用户身份作为独立请求上下文和状态分区。

### 7.2 素材选择与缓存

**AS-01：**每类素材分别解析，推荐优先顺序为用户锁定素材 → 当前可用的已缓存首选来源 → 其他已配置来源 → 默认素材。网络更新不得阻塞当前浏览。

**AS-02：**记录素材来源、更新时间、条目绑定和人工锁定状态。音乐或视频获取器失效，不应让已缓存文件消失。适配器版本变化不要求重新制作所有素材。

**AS-03：**允许维护背景裁切位置、Logo、音乐音量、视频起点、预览时长和声音模式。自动更新不得覆盖人工锁定选择。

**AS-04：**P0 允许人工指定本地文件；P1 增加候选选择、批量缺失诊断和可取消下载任务。可用本地预览应优先于焦点停留时临时联网取流。

**AS-05：**预览缓存可清理，用户手动资产不可误删。临时下载成功后再原子替换；记录空间占用和配额。故障、断网和磁盘不足应产生可恢复状态。

接口适配优先使用公开 API、主题绑定、受支持导出或已验证的缓存格式。不得在主题中硬编码插件 GUID 目录或通过数据库私有字段实现隐式耦合。没有稳定接口的接入标记为实验性，不包装成通用能力。

## 8. Steam 成就与奖杯插件

**定位：第二目标，独立可选插件，不属于最小宿主。**

| 编号 | 功能 | 要求 |
| --- | --- | --- |
| AC-01 | 数据接入 | 首先适配 Steam；优先评估 Playnite Achievements，记录账号、条目和来源 |
| AC-02 | 奖杯页面 | 摘要、列表、解锁状态、解锁时间、完成进度；隐藏成就防剧透 |
| AC-03 | 主题适配 | PS5ish 风格奖杯 UI 与可替换模板，数据逻辑不依赖具体主题 |
| AC-04 | 游戏内通知 | 解锁时显示统一视觉通知与音效，分别验收渲染与数据检测 |
| AC-05 | 通知去重 | 初次导入历史成就不刷屏；重试和重复事件不重复提示 |
| AC-06 | 可卸载性 | 禁用后移除奖杯入口和订阅，游戏启动、主题和预览仍正常 |

Playnite Achievements 已提供主题绑定和通知模板覆盖；其文档说明解锁声音由单独的 UniPlaySong 扩展承担。[S07][S08] 接入可分为数据适配、奖杯展示、解锁事件处理和通知输出，但首个成就插件可在同一个发布包内组织，避免过度拆包。

SAN 作为候选通知实现单独评估。若没有可验证的外部事件输入接口，应按独立通知应用接入，而不是假定宿主可随意向它发送成就对象。当前系统只能管理自己控制范围内的去重；Steam 原生提示或其他应用仍需通过可用设置避免重复。

**AC-07：**单次解锁只启用一条有效通知路径。使用 PA 原生通知或 SAN 原生检测通知时，其所有权和限制必须在设置中可见，不并行启用两套默认弹窗。

**AC-08：**Steam 原始解锁状态与本地奖杯展示规则分离。铜银金、完成徽章或本地白金式标记必须标明规则来源，不描述为 PSN 官方奖杯，不向 Steam 写入伪造成就。

**AC-09：**实时性按来源区分“已检测到事件后的呈现延迟”与“游戏写入到来源可发现的延迟”。不承诺所有 Steam 游戏都能在解锁瞬间被检测。独占全屏、无边框与通知动画兼容性需要逐场景实测。

## 9. Emby 影视插件

**定位：接入同一大屏界面的独立内容插件；浏览与正片播放后端分离。**

**ME-01：**用户配置 Emby 服务器与账号后，增加影视入口和可配置首页分区：最近观看、继续观看、最近添加。三个分区语义不同，不相互替代；剧集可聚合展示，继续观看的主操作指向具体单集和进度。

**ME-02：**完整影视库以 Emby 原生海报墙的视觉和浏览习惯为参考，包含分类、海报网格、筛选和详情；不通过伪造 Playnite 游戏或嵌入需要鼠标操作的网页冒充原生大屏整合。

**ME-03：**选中影视内容后复用剧照、音乐淡入和停留视频逻辑。Emby 已有主题音乐、主题视频、本地预告和最近添加等接口，但媒体是否具有这些素材仍需检查。[S09][S10]

**ME-04：**正片由独立 MediaPlayback 后端处理。浏览插件负责播放意图和内容引用，播放后端负责实际播放、字幕/音轨能力和会话反馈。首版可集成成熟播放器，不要求自研解码器。

**ME-05：**续播、播放开始、进度和停止必须形成 Emby 观看状态闭环；只有打开视频链接不算完成。Emby 提供对应播放状态接口。[S11] 默认禁止预告和主题视频写入正片观看进度。

**ME-06：**断网可浏览已缓存内容；显示服务器连接状态，不阻塞游戏首页。凭证按服务器和用户隔离，日志不记录令牌。恢复连接后按明确会话和时间规则同步，不能用旧离线进度覆盖新的观看状态。

**ME-07：**HDR、音频输出、字幕与复杂片源支持在播放后端兼容表中声明；预告能播放不代表正片功能完整。浏览整合和播放整合采用两个独立里程碑验收。

## 10. 后续游戏内快捷面板

**OV-01：**作为 P3 独立扩展，优先独立进程。通过受控本地通信读取当前游戏与已授权插件能力，使用可重绑定快捷键，避免默认占用已有系统快捷键。

**OV-02：**首个范围为当前游戏信息、追踪奖杯、个人笔记和自定义攻略/工具入口。中文展示与入口可配置是要求，不预装不可替换的服务集合。

**OV-03：**先验收无边框窗口场景，不承诺覆盖全部独占全屏游戏。默认不做游戏进程 DLL 注入，不把打开面板等同于暂停游戏。

**OV-04：**面板输入不得同时误触发游戏操作；关闭后恢复正确游戏焦点。面板故障不应拖垮主界面。暂停游戏、媒体控制、聊天或 AI 能力需要单独需求和插件，不隐式扩大范围。

## 11. 非功能需求

### 11.1 视觉、响应与性能

以下为初始工程目标，不是当前性能实测。M0 使用实际 PC、电视、缩放和手柄建立基准，后续变更通过对比记录判断。

| 编号 | 指标 | 初始目标与条件 |
| --- | --- | --- |
| NF-01 | 视觉一致性 | 首页、详情、加载、缺失素材和插件关闭状态均有基准截图；用户以真实电视效果验收 |
| NF-02 | 焦点响应 | 缓存已热、无网络等待时，输入到可见焦点变化 P95 不超过 100 ms |
| NF-03 | 图片呈现 | 相同条件下，新选中内容的缓存背景 P95 不超过 200 ms；失败保留安全背景 |
| NF-04 | 视频启动 | 参考本地 1080p H.264 素材，在停留阈值到达后首帧目标不超过 1 秒；4K 素材另测 |
| NF-05 | 动画 | 4K 界面以 60 fps 为目标；硬件不足时可降低动态效果，不降低输入响应优先级 |
| NF-06 | 长时运行 | 连续浏览 30 分钟及反复切换后，无持续增长的播放器、订阅和任务；记录资源曲线 |
| NF-07 | 库规模 | P0 至少验证 500 条缓存游戏元数据的导航；图片按需加载，不要求 500 款预告齐备 |
| NF-08 | 游戏运行 | 主页停止音视频及无关预取，不因后台动效持续占用显著解码资源 |

### 11.2 可维护性、恢复与隐私

**NF-09：**核心不引用成就或 Emby 的实现程序集；主题代码不出现第三方账号令牌、数据库路径或网络抓取逻辑。架构检查纳入构建。

**NF-10：**提供安全启动配置，跳过可选插件并加载内置安全主题。主题包应用失败时保持上一可用组合；插件错误显示在诊断而非反复抢占全屏。

**NF-11：**网络请求有超时、取消和合理重试；用户明确操作优先于后台素材任务。默认不上传个人游戏库、观看历史或操作日志。

**NF-12：**插件配置界面说明数据读取和写入范围。凭证使用 Windows 适当的本地保护方案，备份默认脱敏。发布包使用许可明确的图标和资源，并引用用户本地字体；不将未知授权的字体、品牌素材或音效直接随包分发。

## 12. 数据、升级与兼容性

### 12.1 数据所有权

Playnite 继续是游戏库来源，Steam/成就提供者保留原始成就状态，Emby 保留影视库和观看状态。本项目仅保存主题组合、用户覆盖、插件状态、关联标识、可重建缓存和必要同步记录。

安装产物、用户设置、手动资产和缓存必须分开。Playnite 主题安装和更新会替换主题目录，因此不可将唯一一份用户配置或手动素材放在主题安装目录。[S01]

建议统一使用宿主实际提供的用户数据目录，不硬编码 `%APPDATA%`，以保留便携安装适配空间。路径随机器变化的资源以受管理引用表示，导入导出时重新定位。

### 12.2 版本与更新

**UP-01：**分别版本化宿主契约、主题契约、插件清单和插件自有数据 schema。锁定可用的 Playnite、主题和第三方插件组合，保存校验信息。

**UP-02：**升级前保存可恢复配置；新配置迁移成功后原子替换；回滚必须同时考虑程序版本和数据迁移，不能只回滚 DLL。

**UP-03：**P0 只要求手动安装和可重复打包。自动更新为后续能力，不在游玩过程中更新插件或修改已激活主题。

**UP-04：**先针对验证过的 Playnite 主版本开发。旧版插件文档使用 .NET Framework 4.6.2；Playnite 11 开发文档描述了 .NET 10 和明显的 SDK/依赖装载变化。[S12][S13] 因此不承诺同一二进制兼容不同主版本，也不把开发版 API 当作已验证稳定接口。

## 15. 技术假设与风险处理

| 风险或待验证项 | 默认处理 | 不应作出的承诺 |
| --- | --- | --- |
| Playnite 自定义控件的焦点、路由和影视展示边界 | M0 使用真实手柄做最小页面验证；新内容留在自有控件上下文中 | 不保证复制一段 XAML 即可形成通用媒体壳 |
| 插件共享契约、程序集依赖及加载顺序 | 锁定宿主版本，先实现一个真实独立模块；失败时调整承载方式 | 不保证任意 DLL 都能安全并存或热卸载 |
| UniPlaySong 自动行为与宿主时序竞争 | 验证是否可受控；不满足时仅复用素材或替换播放后端 | 不因存在暂停控件就宣称完整媒体控制已实现 |
| EML 视频首帧和释放信号不足 | 经适配测试；不满足则使用同素材的其他后端 | 不将“能播视频”等同于“无黑场且可取消” |
| 第三方成就数据或通知接口不足 | 优先官方公开接入；必要时独立适配或标为实验性 | 不假定 SAN 可接收任意宿主事件，也不保证全游戏即时检测 |
| Emby 主题素材缺失、正片输出复杂 | 浏览降级，正片独立验证 | 不保证有海报就有音乐、预告或完整播放能力 |
| 换主题后可选插件资源不兼容 | 条件装载、默认模板、组合校验和安全主题 | 不承诺任意第三方主题零改动兼容 |

M0 的验证失败应形成架构决策记录，说明替代方案和范围影响。不得悄悄降低关键体验，也不应将未经验证的假设写成已完成能力。

## 16. 开发交付与变更规则

每个功能提交需要关联需求编号、涉及的契约版本、可运行演示和回归用例。P0 交付应包含可安装包、最小安装说明、推荐插件组合、已验证版本表、示例配置、主题/插件扩展说明及安全回退步骤。

新增功能首先判断是否应为插件，只有多个已存在能力共同需要且不含领域规则的职责，才考虑进入核心。新增主题变化首先判断能否通过变量、组件或布局包完成，不为一次视觉改动复制整套主题。

调整优先级、默认声音模式或性能预算时记录理由。只有涉及新用户价值或接口破坏才更新需求版本，不把每个内部重构都当成产品需求变更。

**最终架构约束：主题决定如何呈现，插件决定提供什么能力，宿主负责如何组合和协调。成就、影视或快捷面板都不能成为基础海报墙正常运行的先决条件。**

## 附录 A：拟议清单示例

下列内容仅用于说明扩展边界，不是可直接安装的 Playnite 文件格式。字段与装载实现需要在 M0 确认。

### A.1 主题预设

```json
{
  "id": "theme.ps5ish.midnight",
  "version": "0.1.0",
  "themeContract": "1.x",
  "layout": "layout.ps5ish",
  "palette": "palette.midnight",
  "motion": "motion.soft",
  "icons": "icons.minimal",
  "optionalStyles": {
    "feature.achievements": "styles/achievements.xaml"
  }
}
```

只有对应能力已注册且外观适配兼容时，才加载 `optionalStyles` 中的资源。主题清单不触发联网，也不安装缺失插件。

### A.2 能力插件

```json
{
  "id": "feature.achievements",
  "version": "0.1.0",
  "hostContract": "1.x",
  "entry": "AchievementsModule.dll",
  "provides": ["feature.achievements"],
  "contributesTo": ["details.summary", "details.actions"],
  "requires": ["content.games"],
  "optional": ["notification.output"],
  "activation": "startup",
  "restartRequired": true
}
```

清单表示模块的声明，不意味着源数据接入已完成。插件所需的 PA 或 Steam 适配依赖必须由实际实现进一步声明，禁止通过隐式目录依赖省略。
